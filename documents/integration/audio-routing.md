# 音频、麦克风与 Siri 诊断

入口：Settings → Adapter Configuration → **Audio** → 音频设备 / 声道诊断。

## 先确认输出

分别选择“媒体 / 导航输出”和“Siri / 通话输出”。列表来自 Android 当前对应用可见的
AudioDeviceInfo，包括设备名、类型、地址和报告的声道数。默认沿用系统路由；设备选择
按类型/地址/名称保存，不把每次重启会变化的 device ID 当作永久标识。

播放声道可选双声道、仅左、仅右，实际 AudioTrack 与试听使用同一配置。
诊断页面依次显示语音通话、铃声、导航、音乐，每项独立选择设备、点击“试听”或“停止”。
语音通话设备同时供 Siri 使用；铃声设备同时供适配器 ALERT 使用。
新增导航和铃声设置在首次修改前继承原媒体输出；主动选择“系统自动”后不再继承。
试听与真实播放共用 AudioAttributes 与输出配置，铃声沿用车机现有 SIGNALLING 路由。
每次试听播放六秒内置原创合成旋律：左声道两秒、右声道两秒、双声道两秒。
麦克风输入位于四项输出下方，右侧“显示声波 / 停止声波”按钮控制测试，下方直接显示逐声道波形。
采集源、采集声道数及 Siri 发送声道放在可展开的“麦克风声道设置”中，Siri 命令诊断在“Siri 链路检查”中。
如果全局选择“仅左”，测试右声道阶段应无声；单声道设备或车机混音可能无法物理区分左右。

页面区分 preferred device 的请求结果与 routed device 的实际结果。系统接受请求不保证
路由一定采用；车机未公开的 DSP 通道无法靠普通应用枚举。蓝牙直连手机的音乐绕过
本 App，试听验证的是车机 App 输出。输出偏好立即应用到已创建的实际播放流。

## 找到麦克风与有效声道

1. 在原有 Microphone Source 选择 **App** 并应用，实际 Siri 才会用本机录音上传；
   Phone 模式下本机测试仍可录音，但不能据此判断手机麦克风链路。
2. 选择输入设备，再尝试 VOICE_COMMUNICATION、MIC、VOICE_RECOGNITION 等采集源。
   多声道设备选择采集声道数；1/2 是基础尝试，更高声道仅列出设备报告值，最多 8 声道。
   不支持的采集格式明确报错，不冒充成功。
3. 点击“显示声波”授予 RECORD_AUDIO 权限，说话观察每个声道的波形、RMS dBFS
   和峰值。显示波形放大四倍，数值保持原始电平。噪声也能产生波形，应观察是否随说话变化。
4. 把“发送给 Siri 的声道”设为有语音的那一路，或选择所有声道平均混合。
   采集配置在下次录音开始生效；硬件多声道被抽取/混合成协议要求的 8kHz/16kHz 单声道。
   没有把硬件声道数直接塞进适配器 decodeType。

测试与实际 Siri 共用 MicrophoneCaptureManager 的设备、采集源和声道处理。
测试最长 60 秒，不保存文件、不上传 PCM。离开页面或切到后台会停止测试。
真实 Siri/通话会抢占测试录音，测试不能抢占真实会话。

## 判断 Siri 停在哪一段

“发送 Siri 唤醒测试”走真实命令通道。实体键和测试按钮统一保证至少 300ms 的
按下/松开间隔，避免 OneOS 短按摘要产生紧邻的两个命令；新按下会取消旧的延迟松开。

- 发送失败：先查适配器连接与按键映射，尚不能归因于音频设备。
- 命令已发但一直没有 AUDIO_SIRI_START：适配器或手机未回报启动，麦克风还未进入上传阶段。
- 收到 AUDIO_SIRI_START：页面显示使用 App 还是 Phone/适配器麦克风。
- App 采集中：查看实际输入设备及各声道电平。
- PCM 成功发送字节数增长：仅说明 USB 写入成功，不能证明手机已识别语音。

Siri / 通话录音正在运行时，页面也显示其真实电平，无需另开测试。上传线程的发送异常
会报告出来，避免未捕获异常静默终止定时器。录音器失效时清理采集状态。

## 本地验证

构建 Sideload Debug APK；20 项单元测试通过，覆盖声道抽取、混合溢出边界、
截断帧、逐声道电平、左右声道旋律、麦克风抢占，以及封面先于歌名到达的连续三次切歌。
完整 Lint 仍有 67 个既有错误，本次未增加错误。尚未连接车机，实际端口与 Siri 识别需实车验证。
